# ZanKomek AI — юридический AI-ассистент по законодательству Республики Казахстан

Дипломный проект: юридический AI-ассистент, построенный на архитектуре Retrieval-Augmented Generation (RAG) с независимой серверной верификацией нормативно-правовых источников Республики Казахстан.

Система не ограничивается генерацией текста: каждый нормативный источник, на который опирается ответ, проходит отдельную проверку на стороне сервера, а пользователю показывается явный статус подтверждения информации.

---

## Назначение

Пользователь может:

- ввести юридический вопрос в свободной форме;
- загрузить документ в формате DOCX размером до 1 МБ;
- получить структурированный предварительный правовой анализ;
- увидеть перечень применимых нормативных правовых актов;
- получить ссылку на официальный источник нормы;
- увидеть статус подтверждения информации — подтверждена ли норма официальным источником.

---

## Важное ограничение

> **ZanKomek AI является информационно-справочным инструментом и не заменяет консультацию адвоката, юриста, нотариуса или решение государственного органа.**

Результат работы системы — предварительный анализ для ориентирования в законодательстве. Он не является юридическим заключением и не может служить основанием для юридически значимых действий.

---

## Архитектура

Фактический конвейер обработки запроса:

```
запрос пользователя
      ↓
предобработка (нормализация текста, извлечение текста из DOCX)
      ↓
semantic retrieval (векторный поиск по корпусу НПА)
      ↓
hybrid reranking (переранжирование кандидатов)
      ↓
формирование RAG-контекста
      ↓
генерация ответа (OpenAI API)
      ↓
отдельная серверная проверка официального источника
      ↓
выдача статуса верификации
```

### Архитектурный инвариант

**Semantic retrieval и reranking определяют только релевантность и не имеют права самостоятельно устанавливать `source_confirmed`, `search_confirmed`, `content_checked` или `verification_status`.**

Эти флаги выставляет исключительно отдельный серверный слой верификации, который обращается к официальному источнику независимо от того, что предложил векторный поиск и что сгенерировала языковая модель. Такое разделение не позволяет модели или ранжировщику «самостоятельно подтвердить» норму и является ключевой гарантией достоверности выдачи.

## База знаний

Показатели ниже получены прямым разбором артефактов корпуса, а не оценкой:

| Показатель | Значение |
|---|---|
| Нормативных правовых актов | 7 |
| Статей в корпусе | 1 999 |
| Embedding records | 2 002 |
| Модель эмбеддингов | `text-embedding-3-small` |
| Размерность вектора | 1 536 |
| Стратегия чанкинга | по статьям (`article`) |
| Официальный источник | ИПС «Әділет» — https://adilet.zan.kz |

Количество embedding records (2 002) превышает количество статей (1 999), поскольку несколько объёмных статей были разбиты более чем на один чанк при соблюдении лимита токенов.

### Нормативная база

1. Гражданский кодекс РК — Общая часть
2. Гражданский кодекс РК — Особенная часть
3. Трудовой кодекс РК
4. Предпринимательский кодекс РК
5. Закон РК «О защите прав потребителей»
6. Закон РК «О персональных данных и их защите»
7. Административный процедурно-процессуальный кодекс РК

Все тексты получены из открытой информационно-правовой системы «Әділет».

## Технологии

- **Next.js** — веб-приложение и серверные маршруты API
- **TypeScript** — типизация всей кодовой базы
- **OpenAI API** — генерация анализа и построение эмбеддингов
- **text-embedding-3-small** — модель векторных представлений, 1 536 dimensions
- **RAG** (Retrieval-Augmented Generation) — генерация с опорой на извлечённый нормативный контекст
- **Semantic retrieval** — векторный поиск по корпусу НПА
- **Hybrid reranking** — переранжирование кандидатов, комбинирующее семантическую близость и лексические сигналы
- **Server-side verification** — независимая серверная проверка официального источника
- **Парсинг официальных страниц «Әділет»** — извлечение и очистка текстов статей

## Первые результаты

Benchmark: **20 юридических кейсов**. Полный отчёт — [`data/benchmarks/zankomek_rag_benchmark_20_report.json`](data/benchmarks/zankomek_rag_benchmark_20_report.json).

| Метрика | Значение |
|---|---|
| Law Recall@1 | 0.90 |
| Primary Article Recall@1 | 0.30 |
| Primary Article Recall@3 | 0.35 |

Интерпретация: **выбор нормативного акта уже работает значительно лучше, чем выбор конкретной статьи.** В 90 % случаев нужный закон оказывается на первой позиции, тогда как точная профильная статья попадает на первое место лишь в 30 % случаев.

Повышение Primary Article Recall остаётся направлением дальнейшей работы и зафиксировано как незавершённая задача, а не как достигнутый результат.

## Локальный запуск

```bash
npm install
npm run dev
```

Приложение будет доступно по адресу `http://localhost:3000`.

### Переменные окружения

В корне проекта необходимо создать локальный файл `.env.local` и задать в нём следующие переменные:

- `OPENAI_API_KEY`
- `OPENAI_MODEL`
- `TAVILY_API_KEY`

Реальные значения ключей в репозитории не публикуются и в документации не приводятся — их необходимо получить самостоятельно в личных кабинетах соответствующих сервисов.

> **Файл `.env.local` не должен попадать в Git.** Он исключён правилом `.env*` в `.gitignore`. Перед коммитом следует убедиться, что env-файлы не отслеживаются.

Ключи используются только на стороне сервера. Префикс `NEXT_PUBLIC_*` для них не применяется, чтобы значения не попадали в клиентский бандл.

## Безопасность данных

- В корпусе используются **только открытые тексты законодательства** Республики Казахстан из ИПС «Әділет».
- Документы, загружаемые пользователем, **обрабатываются в оперативной памяти** в рамках обработки запроса и не сохраняются в репозиторий.
- **Конфиденциальные документы не входят в корпус** и не используются при построении эмбеддингов.
- **API-ключи задаются только через переменные окружения** и применяются исключительно на стороне сервера.
- **Ключи не хранятся в репозитории**: env-файлы исключены через `.gitignore`, в коде присутствуют только имена переменных окружения.

## Статус проекта

Создан и протестирован **рабочий прототип**: конвейер RAG с независимой верификацией источников функционирует, покрыт тестами и измерен на benchmark из 20 кейсов.

Дальнейшее развитие направлено на:

- повышение точности выбора конкретной статьи (Primary Article Recall);
- расширение и регулярное обновление нормативной базы с учётом изменений редакций актов.

Проект носит учебно-исследовательский характер и развивается как дипломная работа.
